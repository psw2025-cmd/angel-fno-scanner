# Rebuild the paper-only Angel FNO Scanner

This is a disaster-recovery guide, not a way to recover lost secret values. Never paste passwords or TOTP seeds into issues, commits, chat, screenshots, or logs.

1. Create or regain access to the GitHub repository `psw2025-cmd/angel-fno-scanner`. Restore the protected `main` branch and `test-framework` from verified Git backups or GitHub history. If recreating an empty repository, push the verified original history; do not fabricate past ledger data.
2. Open GitHub **Settings → Secrets and variables → Actions**. Configure the existing `phase2-paper` environment and re-enter four secrets from your authorized password manager / Angel account: `ANGEL_API_KEY`, `ANGEL_CLIENT_CODE`, `ANGEL_PIN`, `ANGEL_TOTP_SEED`. GitHub cannot display old secret values. Rotate compromised values with the broker. Confirm authorized account and broker read-only entitlements.
3. Open **Actions** and enable workflows. Verify `.github/workflows/phase2-angel-paper.yml` and `phase3-angel-pnl.yml` exist on default `main`. Their cron expressions are 09:45 UTC (15:15 IST) and 09:55 UTC (15:25 IST), weekdays. Scheduled GitHub Actions can be delayed or disabled after inactivity; do not infer successful runs from YAML alone.
4. Both workflows must enforce `PAPER_MODE=1`, `LIVE_ORDER_AUTHORITY=0`, use `phase2-paper`, and check out the isolated `test-framework` ledger branch. Confirm Actions permissions permit `contents: write`, environment approvals (if any), and that branch rules permit bot ledger pushes. Do not disable protections to make a failing workflow green.
5. Inspect `phase2/angel_readonly.py`: market-data `getMarketData("FULL",...)` only. No place/modify/cancel order capability is authorized. The option contract master is discovered by `phase2/angel_instruments.py`; verify current expiry and exact tokens.
6. Run Phase 2 manually in GitHub Actions with paper settings. Inspect the workflow's remote SHA verification, `data/paper_ledger/receipt.json`, its `entry_<prediction_hash>.json`, and `data/anomaly_logs/dna_<prediction_hash>.json`. Match prediction/source hashes and 48-or-actual observed contract count; do not assume a fixed universe.
7. Phase 3 default is **previous weekday only** (Monday checks Friday; exchange holidays require calendar-aware validation). `force_intraday` is an engineering test, never certified next-day performance. Confirm the PnL JSON, immutable comparison ledger and `DASHBOARD.md` are pushed to `test-framework`. The `main` dashboard is a separately published verified snapshot, not an automatically synced live page.
8. If a run fails, inspect its job logs and quote timestamps, check broker access, secret presence (not values), contract expiry, source SHA, branch concurrency, and permissions. Never replace real observations with synthetic PASS data. Restore missing historical ledger files from verified Git commits only.
9. Recovery acceptance: test suite and encoding checks pass; Phase 2 real read-only quote capture succeeds; hashes reconcile; Phase 3 calculation passes on eligible receipts; anomalies and unknown IV/Theta are accurately marked; no order APIs; independent review of the dashboard. Keep an off-repository encrypted backup of secrets and Git history under owner control.

No cloud provider, GitHub, or broker guarantees perpetual execution, fresh exchange quotes, investment returns, or holiday handling. Fail closed on missing proof.
