# Phase 3 — Automated theoretical paper PnL tracker

Status: IMPLEMENTED, NOT YET END-TO-END CERTIFIED. Phase 2's successful receipt is immutable evidence; Phase 3 must not rewrite it.

## Critical provenance requirement
The Phase 2 receipt dated 2026-10-15 contains rankings (underlying, expiry, strike, CE/PE, OI, spread) but **does not contain the exact NFO symbol token, tradingsymbol or timestamped entry premium**. Those values cannot be inferred from rankings, current quotes, OI, or the prediction hash. Phase 3 therefore fails closed on this historical receipt rather than inventing entry prices or backfilling a later quote as yesterday's entry. For subsequent daily PnL, produce a separate immutable entry manifest at Phase 2 capture time, bound to the prediction hash and raw snapshot hash, with per-contract exchange=NFO, symboltoken, tradingsymbol, expiry, strike, option_type, captured_at, entry_bid, entry_ask and entry_price_method. Validate each against the raw authenticated FULL quote; never commit credentials or tokens used for authentication. Instrument symbol tokens are public identifiers, not auth tokens. An optional historical source is acceptable only if it is independently timestamped and cryptographically bound to the original snapshot, never retrospectively sampled.

## Daily sequence
At the selected tracking time, read the **latest prior IST calendar-day** receipt from immutable Git history (not merely the mutable receipt.json working copy). Verify receipt/payload canonical SHA-256, source hash, paper safety, source date and uniqueness. Load the separately committed matching entry manifest; verify hash linkage, each entry identity and positive numeric premium. Fetch each exact NFO token with phase2.angel_readonly.AngelReadOnlyProvider, checking the returned tradingsymbol and token. Capture FULL bid/ask with valid bid > 0 and ask >= bid. Conservative long-paper PnL per unit = current bid minus entry ask. Percentage PnL = 100*(current bid-entry ask)/entry ask. No fills, fees, taxes, lot-size PnL or real executable outcome is claimed. Quotes may be stale after close; preserve captured_at and broker exchange timestamp where provided, label snapshot mark-to-market only. Expired or missing contracts fail closed and never silently roll to a new expiry. Reports are append-only by deterministic key (source prediction hash + evaluation IST date); rerun on same day with different result fails rather than overwrite.

## Storage, gates and scheduling
Output `data/pnl_ledger/<prediction_hash>_<YYYY-MM-DD>.json` plus `pnl_report.json` as a transient Actions artifact. The report contains per-contract entry/current bid-ask, absolute/percentage per-unit theoretical long PnL, provenance, input hash and canonical report hash. No BigQuery writes or live orders. Enforce PAPER_MODE=1 and LIVE_ORDER_AUTHORITY=0; use only existing GitHub environment `phase2-paper` secrets. Workflow `.github/workflows/phase3-angel-pnl.yml` supports manual dispatch and weekday IST afternoon schedule (UTC 10:30 = IST 16:00); GitHub scheduled execution may be delayed. No entry manifest means an explicit failed validation and **no PnL certification**. For existing 2026-10-15 receipt, do not fabricate retrospective PnL.

## Upstream schema upgrade
New Phase 2 receipts include `exchange`, `symboltoken`, `tradingsymbol`, `entry_bid`, `entry_ask`, `entry_price` (snapshot ask), `entry_captured_at`, and `entry_price_method` on each ranked row, all derived from the same original authenticated quote capture. A hash-bound immutable `data/paper_ledger/entry_<prediction_hash>.json` manifest is committed alongside the receipt. This is prospective: the prior certified receipt is not rewritten. A Phase 2 capture made today is **not** yesterday's entry; the daily Phase 3 run must wait until the following IST calendar day. Immediate same-day invocation should fail closed, not misrepresent intraday PnL as next-day performance.

## Intraday engineering test mode
Manual workflow dispatch input `force_intraday=true` invokes `python run_phase3_pnl.py --force-intraday-test --push`. This permits only an original receipt captured on the current IST date; it does not bypass receipt SHA, entry manifest, exact token, broker quote, bid/ask, or paper-only checks. Results are marked `INTRADAY_ENGINEERING_TEST_NOT_NEXT_DAY_PNL` and written to a separate `*_INTRADAY_TEST.json` ledger path, never the next-day report. The default scheduled run remains previous-day only. Intraday test proves calculation wiring, not next-day predictive performance.
