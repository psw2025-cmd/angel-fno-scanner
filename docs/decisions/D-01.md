# Decision: D-01 — GATE-06 Formula & Universe Threshold Mismatch

**Defect ID:** D-01  
**Found Date:** 2026-10-05  
**Severity:** HIGH  
**Status:** OPEN  

---

## 1. Description
In the consumer-facing `Formula Checks` sheet tab, GATE-06 checks option contract coverage. The existing formula in Google Sheets was configured as:
`=COUNTA(CE_PE_RANK!C3:C218)=216`
This formula contains two fundamental errors:
1. It queries Column C (`CE_PE_RANK!C3:C218`), which in the actual sheet is either empty or holds option type text rather than the symbol key.
2. It hardcodes `216`, which is an obsolete universe size (the canonical universe was frozen to 219 under PR #13 / `universe_contract.py`), while `CE_PE_RANK` itself represents a ranked view of up to 200 eligible option contracts, not the underlying universe.

## 2. Evidence
From `docs/formula-checks-contract.md`:
```text
GATE-06 observed: =COUNTA(CE_PE_RANK!A5:A204)&" / 200"
GATE-06 status: =IF(COUNTA(CE_PE_RANK!A5:A204)=200,"PASS","FAIL")
```
`CE_PE_RANK` is capped at exactly 200 rows by the ranking publisher in `gainers.py` / `scanner.py`. Relaxing the formula to `>=200` masks truncation or grid overflow defects.

## 3. Impact
- Consumer dashboards reading GATE-06 show a persistent `FAIL` or false error even when the option ranking engine runs successfully.
- If manually relaxed to `>=200`, data loss or partial writes could pass undetected.

## 4. Options Considered
1. **Option A (Recommended):** Update the formula to `=IF(COUNTA(CE_PE_RANK!A5:A204)=200,"PASS","FAIL")` and observed count to `=COUNTA(CE_PE_RANK!A5:A204)&" / 200"`.
2. **Option B:** Change to `>=200`. Rejected because the ranking pipeline deliberately caps the table at exactly 200 eligible contracts whenever 200 exist.
3. **Option C:** Point to `FORENSIC_LIVE` instead. Rejected because GATE-01 already validates `FORENSIC_LIVE!B2:B220 = 219`. GATE-06 is intended specifically for the rank layer.

## 5. Recommended Action
Update the formula on the Google Sheet tab `Formula Checks` at row GATE-06 via an authorized writer session or manual operator action to match `docs/formula-checks-contract.md`.

## 6. Open Questions
- Does `CE_PE_RANK` always have 200 eligible contracts in low-volatility / illiquid sessions, or should there be a fallback min-threshold (e.g. `IF(AND(COUNTA(...)>=150, COUNTA(...)<=200), "PASS", "FAIL")`)?
