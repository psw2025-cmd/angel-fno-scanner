# Decision: D-05 — PUBLICATION_STATUS FAILED_PARTIAL with Blank Digests

**Defect ID:** D-05  
**Found Date:** 2026-10-05  
**Severity:** HIGH  
**Status:** OPEN  

---

## 1. Description
The `PUBLICATION_STATUS` tab in `OPTION_SHEET` recorded a status of `FAILED_PARTIAL` with blank SHA256 digests. This occurs when the publication loop encounters an exception or partial abort after updating initial sheet tabs (e.g. `FORENSIC_LIVE` or `OPTION_PREDICTIONS`) but before completing the BigQuery load and final readback verification.

## 2. Evidence
- In `docs/publication-integrity.md`: Incident `37081049121` where BigQuery `LoadJobConfig` failed after sheet writes completed.
- Latest observed row in `PUBLICATION_STATUS` shows status `FAILED_PARTIAL` and empty hash columns for `forensic_live_sha256`, `option_predictions_sha256`, and `news_live_sha256`.
- `tests/test_publication_integrity.py::test_bq_failure_marks_partial_and_no_false_success` asserts that a BigQuery failure sets status to `FAILED_PARTIAL`.

## 3. Impact
- Downstream systems and verifiers (`verify_publication.py`) treat the entire publication as unverified.
- Consumer dashboards may display inconsistent or stale data across tabs because atomic rollbacks across Google Sheets and BigQuery are impossible.

## 4. Options Considered
1. **Option A (Recommended):** Ensure single-writer execution order runs all preparation and BigQuery validation before advancing publication state, and write digests only upon verified readback.
2. **Option B:** Revert partial Sheet writes on failure. Rejected because Google Sheets does not support transactional multi-tab rollback.
3. **Option C:** Allow consumer read if Sheet succeeded even if BigQuery failed. Rejected: violates single-source-of-truth and multi-sink consistency rules.

## 5. Recommended Action
1. Verify that `eaccdaf` BigQuery schema fix resolves the underlying BigQuery load failure that triggered `FAILED_PARTIAL`.
2. Execute one full authorized run of `market_bot` in staging/production during pre-market to confirm `PUBLICATION_STATUS` flips to `VERIFIED` with non-blank digests.

## 6. Open Questions
- Should `publication.py` implement an explicit staging tab or temporary hide mask during writes to prevent consumers reading mid-flight data?
